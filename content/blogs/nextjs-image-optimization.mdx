The `next/image` component handles a lot out of the box: lazy loading, responsive srcsets, WebP conversion, and preventing layout shift. But the defaults aren't always optimal, and there are a few patterns that make a significant difference.

## Always Specify `sizes`

Without `sizes`, the browser assumes the image might be full viewport width and downloads a larger file than needed:

```tsx
// filename: components/product-card.tsx
// BAD: browser may fetch a full-viewport image for a 300px card
<Image src={product.image} alt={product.name} fill />

// GOOD: tell the browser how wide the image actually renders
<Image
  src={product.image}
  alt={product.name}
  fill
  sizes="(max-width: 640px) 100vw, (max-width: 1024px) 50vw, 300px"
/>
```

## Use `priority` Only on Above-the-Fold Images

`priority` disables lazy loading and preloads the image. It's right for hero images and anything in the initial viewport, wrong for everything else:

```tsx
// filename: components/hero.tsx
<Image
  src="/hero.jpg"
  alt="Hero"
  fill
  priority  // Good — this is the LCP candidate
  sizes="100vw"
/>
```

Adding `priority` to too many images actually hurts performance — the browser delays other resources to fetch them all.

## Avoid Layout Shift with Explicit Dimensions

When using `width` and `height` props (non-fill mode), always set them to the image's intrinsic size or the rendered size. Next.js uses these to calculate the aspect ratio and reserve space before the image loads:

```tsx
// filename: components/avatar.tsx
<Image
  src={user.avatar}
  alt={user.name}
  width={64}
  height={64}
  className="rounded-full"
/>
```

## Blurred Placeholder

For locally imported images, the blur placeholder is automatic. For remote images, generate a `blurDataURL`:

```tsx
// filename: components/cover.tsx
<Image
  src={post.coverImage}
  alt={post.title}
  fill
  placeholder="blur"
  blurDataURL="data:image/png;base64,iVBORw0KGgo..." // tiny base64 placeholder
  sizes="(max-width: 768px) 100vw, 50vw"
/>
```

A common approach is to generate a 10×10 pixel version of the image during build and embed it as the blur placeholder.

## Remote Patterns

Never use a wildcard domain in `remotePatterns`. Be as specific as possible:

```ts
// filename: next.config.ts
images: {
  remotePatterns: [
    {
      protocol: 'https',
      hostname: 'cdn.sanity.io',
      pathname: '/images/**',
    },
  ],
},
```

These small configuration choices compound across a large image-heavy site into significant LCP and CLS improvements.
